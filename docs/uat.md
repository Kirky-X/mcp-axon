# 用户验收文档（UAT）
**需求链化管理系统 - User Acceptance Testing**

---

## 1. 验收测试概述

### 1.1 验收目标
- 验证系统满足所有产品需求（PRD）
- 确认 AI 能顺畅完成需求管理流程
- 验证系统在真实场景下的可用性和用户体验

### 1.2 验收标准
- ✅ 所有核心功能正常工作
- ✅ AI 交互体验流畅自然
- ✅ 性能达到承诺指标
- ✅ 异常场景有合理提示
- ✅ 数据一致性得到保证

### 1.3 验收参与方
- **产品经理**：验证功能完整性
- **AI 测试员**：验证 AI 交互体验
- **技术负责人**：验证技术实现质量
- **最终用户**：验证实际使用场景

### UAT-001: 项目创建与管理 ⏳ 待验收

**验收场景**：创建新项目并查看状态

**前置条件**：
- MCP 服务器已启动
- Claude AI 已连接

**测试步骤**：
1. AI 调用 `create_project` 工具

3. AI 调用 `get_project_state` 查询项目状态

```json
  "status": "CREATED",
  "next_action": "add_root_requirement",

```

**验收标准**：
- ✅ 项目创建成功，返回唯一 ID
- ✅ 状态初始化为 `CREATED`
- ✅ 提供下一步操作建议
- ✅ 错误输入时有明确提示

### UAT-002: 需求添加与复杂度评估 ⏳ 待验收

**验收场景**：添加根需求并获得分解建议

**前置条件**：
- 已创建项目

**测试步骤**：
1. AI 调用 `add_requirement` 工具

2. 验证返回 `needs_decomposition: true`
3. 验证返回 `decompose_hints` 包含合理建议
4. AI 添加简单需求："修改用户头像"
5. 验证返回 `needs_decomposition: false`

**预期结果**（复杂需求）：
```json
{
  "requirement_id": "req_001",
  "status": "draft",
  "level": 0,
  "complexity_score": 0.85,
  "needs_decomposition": true,
  "decompose_hints": [
    "考虑用户注册、登录、权限管理等子模块",
    "考虑按功能模块、技术层次或用户角色进行分解"
  ],
  "next_action": "decompose"
}
```

**验收标准**：
- ✅ 复杂需求（>200字，含关键词）被正确识别
- ✅ 简单需求不建议分解
- ✅ 分解提示有实际参考价值
- ✅ 层级关系正确计算

**实际结果**：⏳ 待验收

**预期结果**：
```json
{
  "requirement_tree": {
    "req_001": {
      "content": "用户管理系统",
      "level": 0,
      "children": ["req_002", "req_003", "req_004"]
    },
    "req_002": {
      "content": "用户注册功能",
      "level": 1,
      "parent": "req_001"
    }
  }
}
```

**验收标准**：
- ✅ 父子关系正确建立
- ✅ 层级深度自动计算
- ✅ 支持多层嵌套（至少 5 层）
- ✅ 需求树结构清晰可查询

**实际结果**：⏳ 待验收

- ✅ 依赖关系能正确设置和查询

- ✅ 测试用例以 JSON 格式正确存储
- ✅ 验证节点与需求一对一关联
- ✅ 添加验证后自动检查链化条件

## 3. 异常场景验收

### UAT-011: 并发锁机制验收 ⏳ 待验收

**验收场景**：多个 AI 会话尝试同时操作同一项目

```json
{

```

**验收标准**：
- ✅ 同一时间只有一个会话能操作
- ✅ 被拒绝时有明确提示
- ✅ 锁自动释放（操作完成或超时）
- ✅ 锁超时后其他会话能接管

**实际结果**：⏳ 待验收

**业务背景**：

**完整流程**：

   ```
   系统: [创建成功] 项目 ID: proj_ecommerce
   ```
