# 产品需求文档（PRD）
**需求链化管理系统 - Requirement Chain System**

---

## 1. 产品概述

### 1.1 产品定位
需求链化管理系统是一个基于 MCP 协议的智能需求管理工具，通过 AI 交互式对话机制，帮助用户将复杂项目需求逐层分解，并自动构建可执行的需求链表。

### 1.2 目标用户
- **主要用户**：使用 Claude AI 进行项目管理的开发者、产品经理
- **使用场景**：
  - 复杂软件系统的需求分解与规划
  - AI 辅助的项目任务拆解
  - 需求依赖关系可视化管理

### 1.3 核心价值
- 将抽象需求逐步细化为可执行的叶子任务
- 自动处理需求依赖关系的传递
- 通过拓扑排序生成最优执行链
- AI 驱动的交互式需求管理体验

#### 并发控制机制说明

本系统采用**两层并发控制机制**，确保数据一致性和操作安全性：

**1. 项目级锁（Project Lock）**
- **作用范围**: 整个项目
- **控制粒度**: 粗粒度，防止多会话同时操作同一项目
- **实现方式**: 项目表中的 `locked_by` 和 `locked_at` 字段
- **适用场景**: 任何需要修改项目数据的操作
- **工作原理**:
  - 会话开始操作时自动获取项目锁
  - 锁定期间其他会话只能读取，不能修改
  - 会话结束或超时后自动释放锁
- **超时时间**: 30 分钟无操作自动释放

**2. 乐观锁（Optimistic Lock）**
- **作用范围**: 单个需求节点
- **控制粒度**: 细粒度，防止并发更新同一需求
- **实现方式**: 需求表中的 `version` 字段
- **适用场景**: 更新需求内容、更新需求状态等操作
- **工作原理**:
  - 读取需求时获取当前 version 值
  - 更新时检查 version 是否未变
  - 如果 version 已变，说明有其他操作已更新，拒绝本次更新
- **冲突处理**: 抛出版本冲突异常，提示用户重新获取最新数据

**两层锁的关系**:
- **项目锁是第一层防护**: 确保同一时间只有一个会话能操作项目
- **乐观锁是第二层防护**: 在项目锁保护下，防止并发更新冲突
- **互补关系**: 项目锁防止跨会话并发，乐观锁防止同会话内的并发问题
- **性能优化**: 项目锁减少了乐观锁冲突的概率

**使用示例**:
```
场景: 两个会话同时尝试更新需求 A

会话 1:
1. 获取项目锁（成功）
2. 读取需求 A（version=1）
3. 修改需求 A
4. 更新需求 A（version=1 → 2，成功）
5. 释放项目锁

会话 2:
1. 尝试获取项目锁（失败，被会话 1 持有）
2. 等待或提示用户稍后重试

结果: 会话 2 无法获取锁，避免了并发冲突
```

```
场景: 同一会话内并发更新需求 A

操作 1:
1. 读取需求 A（version=1）
2. 修改需求 A
3. 更新需求 A（version=1 → 2，成功）

操作 2（同时执行）:
1. 读取需求 A（version=1，旧版本）
2. 修改需求 A
3. 更新需求 A（version=1 → 2，失败，version 已变为 2）

结果: 操作 2 失败，提示版本冲突，需要重新读取
```

#### FR-013: 拓扑排序算法 ✅ 已实现
**用户故事**：作为系统，我需要根据依赖关系生成需求的执行顺序。

**功能描述**：
- 基于 Kahn 算法的拓扑排序
- 支持分层输出（便于识别并行节点）
- 检测循环依赖

**算法流程**：
```
1. 构建邻接表和入度表
2. 将入度为0的节点加入队列（第0层）
3. 逐层处理：
   - 取出当前层所有节点
   - 更新邻居节点入度
   - 入度变为0的进入下一层
4. 若还有节点入度>0，说明存在环路
```

**验收标准**：
- 生成分层结果 `[[layer0], [layer1], ...]`
- 检测到环路抛出异常
- 单层多节点识别为并行节点

**实现文件**：`src/utils/graph.py`, `src/services/chain_builder.py`
**实现状态**：✅ 完整实现
- GraphAlgorithms.topological_sort() 完整实现
- Kahn 算法完整实现
- 分层输出支持已实现

### 7.1 术语表
- **需求节点**：需求树中的一个需求单元
- **叶子节点**：不再分解的最终需求
- **链化**：将需求节点按依赖关系组织成链表的过程
- **拓扑排序**：根据依赖关系确定执行顺序的算法
- **并行节点**：可以同时执行的需求节点
